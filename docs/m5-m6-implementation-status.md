# M5·M6 구현 결과

기준일: 2026-10-14. 기존 M0–M4 위에 추가한 로컬 구현입니다. 외부 Vercel/Supabase 운영 프로젝트는 변경하지 않았습니다.

## M5: 평가와 학습 기록

- 세트 등록 시 선택 문장 전체를 평가 코호트에 포함합니다. 처음 입력 회상을 제출한 시점부터 7일 평가(5–9일), 30일 평가(27–33일)의 창을 고정합니다. 아직 시작하지 않은 문장도 별도로 표시합니다.
- 유지 평가는 첫 학습 당시의 문장 버전을 기준으로 합니다. 주간 누적 평가는 최대 회상 5문항과 검수된 응용 2문항을 배정합니다. 배정과 제출은 사용자 잠금 아래 처리합니다.
- 평가 첫 제출 전에는 힌트·정답을 공개하지 않습니다. 오늘 학습과 겹치는 같은 버전 문항은 한 제출 이벤트에 연결해 중복 채점과 복습 상태 중복 갱신을 막습니다.
- 응용 문항은 자체 정답과 설명으로 채점하며 일반 문장 회상 상태를 올리지 않습니다. 같은 문장의 노출 간격에는 반영합니다.
- 배정 수, 응시 수, 기간 내 정답, 미응시, 기간 밖 응시를 구분합니다. 7일/30일은 첫 학습 이후 평가 시점이며, 그동안 한 번도 보지 않았다는 뜻이 아닙니다. 직전 노출 간격과 중간 회상 횟수를 저장합니다.
- 내 문장에 메모·숨김·자기 체크·신고를 추가했습니다. 자기 체크와 입력 회상 증거는 별도입니다. 서로 다른 3일의 유효 회상과 마지막 7일 이상의 노출 간격으로 ‘지연 회상 확인 이력’, 이후 30일 이상의 간격을 둔 회상으로 ‘유지 확인 이력’을 표시합니다. 과거 검증 이력을 나타내며 현재 암기를 보장하지 않습니다.
- 달력은 실제 학습 당시의 날짜 스냅샷을 집계합니다. 날짜가 없는 과거 기록은 UTC 대체 집계로 표시합니다. 예정 학습은 세션의 현지 날짜를 사용하고, 평가일은 UTC 표시 기준을 안내합니다.
- 관리자 응용 문항은 초안→검수→발행→보관 절차와 발행 후 불변성을 적용합니다. 신고 처리와 품질 집계 화면을 분리했습니다. 관리자 품질 화면에 개인 메모나 답안 원문은 보내지 않습니다.

## M6: 설치, 알림, 답안 복구

- manifest, 일반·maskable 아이콘, iPhone 설치 안내, 공개 오프라인 안내 화면을 추가했습니다.
- 서비스워커는 공개 안내와 아이콘만 캐시합니다. 로그인 페이지, 사용자 페이지, API, RSC, 정답, 음원을 오프라인 캐시에 저장하지 않습니다.
- 제출 직전에 이벤트 ID·답안·자기평가 값을 고정해 `sessionStorage`에 임시 보관합니다. 같은 탭에서 새로고침·재연결·수동 재시도가 가능하며, 서버에서 확인된 응답만 완료 처리합니다. 사용자/세션으로 분리하고 최대 20건·24시간으로 제한하며 로그아웃 시 지웁니다. 탭을 닫은 뒤의 복구와 완전 오프라인 학습은 지원하지 않습니다.
- 푸시 권한 요청은 사용자 동작으로만 시작합니다. 거절·미지원 시 오늘 학습 화면으로 계속 사용할 수 있습니다. 조용한 시간과 수신 해제를 설정할 수 있습니다.
- 서버는 VAPID, 제공자 제한, 사용자 동의, 학습 일정·일시정지·만료를 검사합니다. 일자/기기별 발송 행과 임대 토큰을 사용해 중복 Cron 실행을 제어하고, 만료 구독을 해제하며 일시 오류를 재시도합니다.
- Supabase Cron/Vault SQL 템플릿을 제공합니다. Preview와 로컬 발송은 비활성화하고 스테이징은 명시한 사용자만 허용합니다. 네트워크 발송의 정확히 한 번 전달은 보장하지 않습니다. 자세한 제약은 [푸시 안내](push.md)를 참고하세요.

## DB와 로컬 실행

- 로컬 Supabase PostgreSQL을 그대로 사용합니다. `20261014020000_assessments_push` migration은 평가·응용 문항·신고·알림 테이블과 기존 기록 필드를 추가하며 기존 학습 기록을 삭제하지 않습니다.
- 기존 로컬 DB에 적용했고, 별도 빈 DB에서도 전체 migration 적용을 확인했습니다.
- 샘플에는 응용 문항 2개를 추가했습니다. 시연용 콘텐츠이며 상용 언어 검수를 대신하지 않습니다.
- 런타임은 제한된 `app_runtime` 역할, migration은 관리자 연결을 사용합니다. 배포 순서는 [배포 안내](deployment.md)를 따릅니다.

## 검증과 남은 실환경 확인

`pnpm verify:full` 최종 통과:

- ESLint, Prisma/Next 타입 생성, TypeScript 통과
- 단위 테스트 48개, 실제 PostgreSQL 통합 테스트 74개 통과
- 프로덕션 빌드 통과
- 모바일 Chromium E2E 10개 통과: 기존 가입·메일·콘텐츠·학습·일정 회귀, 주간 회상/응용·메모·신고·달력·관리자 화면, 푸시 권한 거절/미지원, 서비스워커 캐시 제한, 서버 저장 후 응답 유실·재전송 1회 기록·로그아웃 대기 답안 정리
- 360px 평가·달력·관리자 화면 가로 넘침 검사와 스크린샷 검토
- 전체 3개 migration의 빈 DB 적용, 로컬 seed, 프로덕션 의존성 감사 통과
- Cron 템플릿을 로컬 트랜잭션에서 설치하고 발송 SQL을 PREPARE한 뒤 롤백: 예약 작업과 외부 발송을 남기지 않음

검증 로그: `.omx/artifacts/m56-verify.log`. `pg`의 같은 클라이언트 병렬 query 사용에 대한 deprecation 경고가 남아 있습니다. 현재 검증은 통과하지만 pg 9 업그레이드 전 Prisma adapter의 호환성을 다시 확인해야 합니다.

M7에서 별도 스테이징의 HTTPS·Vercel 함수·Supabase Cron/Vault를 연결하고 실제 iOS/Android 설치, 푸시 수신과 클릭을 확인해야 합니다. 로컬 모의 발송 테스트는 실제 푸시 제공자의 전달 품질을 증명하지 않습니다. 완전 오프라인 문장팩, 음성 인식/AI 채점, 운영 배포는 이번 범위에 포함하지 않습니다.
