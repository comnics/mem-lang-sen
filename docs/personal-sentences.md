# 직접 만든 개인 문장

## 이용 흐름

`내 문장 → 직접 만든 문장 → 개인 세트 만들기`에서 시작합니다. 기존 **연습 기록** 화면은 그대로 유지합니다. 개인 세트는 본인만 볼 수 있으며 관리자 공용 콘텐츠 목록에도 표시하지 않습니다. 공유·번역 AI·TTS·음원 업로드·영구 삭제는 제공하지 않습니다.

1. **직접 입력**: 한국어 질문/상황과 영어 정답을 각각 입력하고 행 추가/제거/위아래 이동을 합니다. `직접 입력 서버 미리보기`에서 오류와 중복 개수를 확인한 뒤 `직접 입력 전체 저장`을 누릅니다. 미리보기 후 입력을 바꾸면 다시 서버 미리보기를 해야 합니다.
2. **파일**: 아래 형식의 파일을 선택하고 `파일 미리보기`를 누릅니다. 여러 시트가 있으면 시트를 고른 뒤 다시 미리봅니다. 오류 행을 수정하거나 직접 제거하고 `수정 내용 서버 재검증 → 미리보기 전체 저장`을 누릅니다. 한 행이라도 오류가 있으면 **아무 행도 저장하지 않습니다**. 오류가 없는 중복 행은 건너뛰고 수량을 알립니다.
3. **학습 등록**: 저장과 등록은 별개입니다. `내 세트로 등록` 후 입력 회상/말하기 자기확인 또는 `오늘 / 복습`으로 이동합니다. 공용 문장과 같은 통합 일일 예산·복습 우선 규칙을 사용합니다. 새 문장 60초/복습 30초의 기존 예산 규칙은 바꾸지 않습니다.
4. **저장 후 수정**: `정답을 보고 저장 문장 편집 열기`를 누릅니다. 정답을 보기 전에 명시적인 POST로 작성 노출을 기록하며, 목록 GET은 정답을 반환하거나 노출 상태를 변경하지 않습니다. 수정은 새 버전으로 저장합니다. 기존 진도/일정/답안/7·30일 평가 기준 버전은 유지됩니다. 새 학습 주기는 새 문장으로 추가하세요. 구버전이 들어 있는 진행 중 세션은 자율 연습까지 만료됩니다. 이미 제출한 답안 재전송은 저장된 결과를 돌려줍니다.
5. **보관/복구**: 세트나 문장을 보관하면 신규 학습 대상에서 제외하고 기록은 보존합니다. 세트 보관은 등록을 일시정지합니다. 복구만으로 일시정지를 해제하지 않으며 사용자가 `자동 큐 재개`를 눌러야 합니다. 빈 세트를 복구하면 작성 중(DRAFT)으로 돌아갑니다.

음원이 없어도 입력 채점과 말하기의 텍스트 비교·자기확인을 사용할 수 있습니다. 말하기는 자동 음성 인식/채점이 아닙니다. 정답 편집 열기/저장 등으로 정답을 본 날은 기존 노출 규칙에 따라 평가를 미룹니다. 7/30일 유지 평가는 편집 전 기준 문장으로 제시될 수 있습니다.

## 입력 한도

- 질문과 정답: 각각 정규화 후 1~500자. 보조 설명/힌트는 선택, 각각 최대 500자. 제출 후 해설은 선택, 최대 1,000자.
- 허용 답안: `|`로 구분, 대표 정답 자동 포함·중복 제거 후 최대 12개. 영어(en), A1/A2/B1만 지원합니다.
- NFC·앞뒤 공백·연속 공백만 정리합니다. 중복 비교에서 대소문자와 구두점을 보존하고 `(질문,정답)` 쌍이 같은 세트 안에서 같을 때만 건너뜁니다. 타인의 문장 존재 여부는 알려주지 않습니다.
- 파일 2MiB, 미리보기/세트 최대 100문장(보관 문장 포함), 사용자 활성 개인 문장 최대 1,000개. 보관 세트/문장은 활성 사용자 한도에서 제외하며 복구할 때 다시 확인합니다.
- XLSX ZIP 항목 최대 200, 실제 압축 해제 총합 16MiB, 단일 항목 4MiB. 메타데이터 포함 XML 노드/깊이/문자열/셀/시트 한도와 5초 종료 제한이 있습니다. 문장 시트는 A:G, 헤더 포함 101행까지입니다. 실행기당 동시에 2개, 사용자당 실행기 기준 분당 10회까지 파일/직접 미리보기를 처리합니다. 다중 인스턴스의 분산 rate limit은 인프라 계층에서 추가 적용하세요.

## XLSX

[실제 예제 다운로드](/templates/personal-sentences.xlsx)

1행 헤더: `prompt,target` 필수. 선택 `meaning,acceptedAnswers,hint,explanation,level`. 순서는 바꿔도 되며 헤더 없는 데이터 열, 알 수 없는/중복 헤더는 거절합니다. 텍스트 셀로 저장하세요. 수식은 계산 결과가 캐시되어 있어도 거절합니다. 숫자/날짜/오류/논리 셀, 하이퍼링크, 외부 참조, 매크로, 병합 셀, 손상 XML/ZIP, 암호화, XLS/XLSM은 지원하지 않습니다. 여러 시트는 자동 합치지 않습니다. 보안을 위해 선택하지 않은 시트와 XML 메타데이터도 위험 요소를 검사합니다. 스타일에 사용된 병합 셀도 보수적으로 거절합니다.

### Node production 배포

XLSX는 Node 24 worker를 사용하므로 Edge runtime으로 배포하지 않습니다. worker에 넘길 `sax` 경로는 `createRequire(<실행 앱 루트>/package.json)`로 실행 시점에 해석합니다. `import.meta.url` 기반 `require.resolve`는 Turbopack에서 숫자 module ID로 바뀔 수 있어 사용하지 않습니다. `next start`는 앱 루트에서, standalone은 배포된 `server.js`가 있는 디렉터리에서 실행하세요(standalone 서버도 이 디렉터리로 cwd를 설정합니다). 소스 머신의 경로나 별도 전역 node_modules를 참조하지 않습니다.

`next.config.ts`의 `serverExternalPackages: ['pg', 'sax']` 및 preview route용 `outputFileTracingIncludes`를 유지하세요. eval worker의 동적 require는 자동 tracing만으로 충분하지 않습니다. 배포 artifact의 해당 route `.nft.json`에 실제 `sax/lib/sax.js`와 package metadata가 포함되는지 확인하고, production 서버에서 실제 예제 XLSX를 업로드해 미리보기/전체 저장을 검증해야 합니다. 단위 테스트만으로 bundling 또는 serverless provider 호환성을 검증했다고 간주하지 않습니다.

## TXT

엄격 UTF-8(BOM 허용), LF 또는 CRLF. 잘못된 UTF-8과 NUL은 거절합니다. 빈 줄은 무시하고 원본 행 번호를 유지합니다. 구분자를 추측하지 않습니다.

- [영어 한 줄 예제](/templates/personal-sentences.lines.txt): `영어 한 줄씩` 모드를 선택합니다. target만 채우므로 **미리보기에서 질문을 직접 작성해야** 저장할 수 있습니다. 정답을 질문으로 복제하거나 자동 번역하지 않습니다.
- [TSV 예제](/templates/personal-sentences.tsv.txt): `탭 2/3열` 모드를 선택합니다. 헤더 없이 `한국어 질문<TAB>영어 정답[<TAB>보조 설명]`. 파일 전체 열 수를 동일하게 맞춥니다. 셀 안의 탭/줄바꿈/escape 문법은 지원하지 않습니다.

## 실패·개인정보·운영

- 입력/미리보기는 브라우저 메모리에만 있고 영구 자동 저장/오프라인 업로드는 제공하지 않습니다. 저장 실패·409 충돌 때 입력을 유지합니다. 최신 상태를 다시 불러온 뒤 입력을 확인하고 새 서버 미리보기로 재시도하세요. 브라우저 종료·페이지 이동은 미저장 경고를 제공합니다.
- 원본 파일·원본 파일명은 DB/Storage/로그에 저장하지 않습니다. 미리보기 정규화 행은 30분 동안만 commit 가능하며 완료 시 즉시 비웁니다. 만료 원문은 후속 미리보기 생성 요청에서 전역 최대 20개씩 비우는 bounded cleanup을 수행합니다. 따라서 30분은 접근/commit TTL이고, 물리 삭제 SLA는 아닙니다. 엄격한 시간 기반 파기가 필요한 운영 환경은 별도 승인한 정리 작업을 배치해야 합니다. 완료 멱등 메타데이터는 7일 이후 owner 요청에서 최대 20개씩 정리합니다. 학습 이력과 활성 콘텐츠는 정리하지 않습니다.
- 새 쓰기 API는 requireUser의 검증된 Auth UUID를 owner로 사용합니다. 세션에 바인딩된 CSRF cookie + custom header를 검사합니다. 실제 access token은 저장/반환/로그하지 않고 서버에서 결합 해시 계산에만 사용합니다. 토큰 endpoint 응답과 개인 API는 private/no-store입니다. 기존 전역 Origin 정책을 변경하지 않았습니다.
- 편집/가져오기 commit은 사용자 → 세트 → 문장 순으로 잠그고 revision/version 충돌은409입니다. import commit은 owner/preview/hash/revision/세트/UUID key에 묶습니다. 같은 키/같은 내용 재전송은 같은 결과이며 다른 preview/내용은409입니다.
- 보관/수정은 SessionItem/ReviewEvent를 삭제하지 않습니다. 영향을 받는 ACTIVE 세션은 ABANDONED, 해당 세션의 미응답 평가 연결만 해제합니다. 평가 assignment와 분모, 응답 이력/기준 버전은 보존합니다.

## 파서 선택 근거와 검증 상태

- ZIP은 Node 24 `zlib.inflateRawSync`의 `maxOutputLength`로 실제 해제 크기를 제한하고 CRC/중앙·로컬 헤더/중복·경로/암호화 등을 제한하는 좁은 OOXML reader입니다. 디스크에 풀거나 외부 URL을 가져오지 않습니다.
- XML은 SAX strict 모드, `sax@1.6.1` 정확 버전입니다. DTD/ENTITY를 사전 거절하고 XML을 코드로 평가하지 않습니다. `saxes` 저장소는 보관 상태였으므로 선택하지 않았습니다. 별도 worker에 정적 신뢰 프로그램만 전달하며 업로드는 데이터입니다. 5초 초과 시 worker를 실제 종료합니다. XLSX 패키지/npm의 오래된 `xlsx`는 사용하지 않습니다.
- 선정 조회: [sax 공식 저장소](https://github.com/isaacs/sax-js), [npm 정확 배포 정보](https://registry.npmjs.org/sax/1.6.1), [GitHub Advisory 검색](https://github.com/advisories?query=ecosystem%3Anpm+sax), [Node zlib 문서](https://nodejs.org/docs/latest-v24.x/api/zlib.html). 이 조회는 보안 인증/취약점 부재 보장이 아닙니다. 배포 전 advisory와 실제 자원·worker bundling을 최종 캠페인에서 확인해야 합니다.

**현재: 구현과 테스트 작성만, 테스트 실행/빌드/타입검사/브라우저/최종 리뷰 미실시.** 격리 환경에서 기존 `pnpm verify:full`을 실행하고 새로운 unit/integration/E2E 및 migration/공용 회귀를 최종 검증합니다. 운영 DB/실제 비밀값을 연결한 호스트에서 실행하지 마세요.
