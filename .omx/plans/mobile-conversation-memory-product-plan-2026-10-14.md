# 필수 회화 문장 암기 서비스 기획안 v0.2

작성일: 2026-10-14. 범위: 제품·학습·운영·기술 기획. 구현 및 외부 서비스 도입은 미실행.
최초 조사 시 작업 디렉터리는 비어 있었으며 현재는 기획 문서만 있다. 아래 코드 경로는 모두 향후 구현 제안이다.
2026-10-14 사용자 지정 반영: Next.js 최신 안정 버전 + PostgreSQL + Prisma, Vercel + Supabase 배포. 상세 구현 순서와 버전·운영 기준은 [개발 실행 계획](implementation-plan-nextjs-supabase-2026-10-14.md)을 따른다.

## 1. 목적과 기본 가정

**사용자가 선택한 필수 문장을 정답 없이 꺼내 쓰고, 시간이 지나도 유지하도록 돕는다.**

‘무조건 외우게 한다’는 목적을 제품 규칙으로 바꾼다. 읽거나 체크한 것만으로 완료시키지 않고, 실제 회상 결과로 다음 학습을 정하며, 실패한 문장은 재학습에 자동 편입한다. 앱이 모든 사람의 영구 암기를 보장할 수는 없으므로 회상 성공·유지 기간·미검증 범위를 정확히 보여 준다.

- 1차 대상 가정: 한국어를 사용하는 성인 영어 초급~중급자. 여행·일상 중심.
- 첫 출시: 모바일 웹. 설치 없이 시작하고 PWA 설치·알림은 선택 제공.
- 데이터는 다국어를 고려하되 출시 콘텐츠와 채점 규칙은 영어부터 검증.
- 기본 학습량 가설: 하루 10분, 신규 3~5문장. 짧은 3분 복습도 제공.
- 수익화, 아동 대상 운영, 교육기관 관리, 고급 자유회화는 초기 범위 밖.
- 개발 기간·비용은 인원, 콘텐츠 제작 방식, 배포 환경 확정 전 산정하지 않는다.

## 2. 학습 근거와 설계 해석

| 근거 | 앱에 적용할 설계 | 해석의 한계 |
|---|---|---|
| 외국어 단어 학습에서 반복 인출이 지연 회상에 이점을 보인 실험 [S1] | 정답을 먼저 가리고 사용자 답변 후 피드백 | 단어 실험만으로 문장 회화 효과의 크기를 보장하지 않음 |
| 복습 간격과 목표 유지 기간이 함께 성과에 영향을 준 실험 [S2] | 간격을 둔 복습, 목표일·최근 노출 간격 기록 | 모든 사람에게 동일한 최적 간격이 존재한다고 주장하지 않음 |
| 여러 세션에 걸친 성공적 재학습을 조사한 연구 [S3] | 당일 정답과 여러 날 유지 성공을 분리 | 특정 성공 횟수를 학술적으로 확정된 기준처럼 표시하지 않음 |
| 다른 예시를 회상·적용하는 연습이 새로운 예시로의 전이에 도움을 준 실험 [S4] | 같은 문장을 다른 상황 단서·패턴 변형으로 시험 | 실제 대화 전이는 별도의 말하기 평가가 필요 |

이하 문장 수·간격·통과 기준·지표 목표는 검증할 제품 가설이다. 문장 암기, 듣기 이해, 말하기 수행을 같은 능력으로 합산하지 않는다.

## 3. 콘텐츠 구조: 문장 원본 → 묶음 → 사용자 학습 계획

관리자는 ‘학습 세트’를 발행하고 사용자는 세트를 내 학습에 추가한다. 세트는 문장을 참조하는 모음이며 같은 문장을 여러 세트에 재사용할 수 있다.

| 분류 | 예시 | 학습 목적 |
|---|---|---|
| 상황별 | 카페 주문, 길 묻기, 호텔 체크인, 식당 요청 | 상황을 보고 필요한 표현 회상 |
| 패턴별 | Could you…?, I'd like to…, Is there…? | 핵심 구조를 외우고 슬롯 교체 |
| 기능별 | 부탁, 확인, 거절, 설명 요청, 사과 | 의사소통 의도에 맞는 표현 선택 |
| 목표별 | 여행 핵심 100문장, 첫 업무 미팅 | 여러 세트를 목표에 맞게 구성; 2차 확장 |

초기 콘텐츠 제안: 세트 약 10개, 세트당 10~20문장, 중복 제외 약 150문장. 마이크로 세션은 3~5문장이다. 세트 크기와 하루 학습량을 분리한다.

‘필수’ 선정은 사용 빈도·범용성·의사소통 실패 시 중요성·학습 수준을 기준으로 편집자가 판정한다. 빈도 근거가 없으면 ‘가장 많이 쓰는 문장’으로 홍보하지 않는다. 출처·권리·검수자를 저장한다.

문장 필수 필드:

- 언어, 표준 문장, 자연스러운 한국어 의미, 짧은 상황 설명, 난이도·말투·지역 태그.
- 목표 표현/패턴, 핵심 의미 요소, 허용 답안, 자주 틀리는 부분, 단계별 힌트.
- 정답을 노출하지 않는 상황 질문, 필요하면 상대방 대사, 패턴 변형 예시.
- 검수된 표준 음원, 대본, 음원 출처·이용 권한. 느린 재생 기능.
- 콘텐츠 버전, 검수자, 발행 상태, 수정 사유.

예: ‘창가 좌석을 정중하게 요청하세요’ → “Could I have a window seat, please?” 허용 표현은 상황과 목표 패턴에 맞춰 편집한다. 의미가 통하는 대체 문장과 목표 패턴 재현 성공을 별도 기록한다.

학습 단위는 사용자×문장×회상 유형이다. 동일 문장을 다른 세트에서 추가해도 이력과 복습을 중복 생성하지 않는다. 상황별 다른 단서는 같은 문장의 연습 변형으로 관리한다. 듣기·패턴 응용이 추가되면 해당 능력 상태는 별도로 관리한다.

## 4. 사용자 경험

### 첫 방문

1. 예제 3문장으로 ‘보고 이해 → 가리고 답하기 → 다시 확인’ 체험.
2. 언어·목적·대략적인 수준 선택.
3. 추천 세트를 미리 보고 선택. 고정된 성격 진단 대신 짧은 회상 사전 점검.
4. 학습 요일 또는 N일 간격, 시간대, 하루 시간, 선택적 목표일 설정.
5. 기록 동기화 시 로그인. 알림 권한은 학습 가치를 경험한 뒤 사용자 동작으로 요청.

### 하단 탐색

| 화면 | 핵심 내용 |
|---|---|
| 오늘 | 오늘 예정 복습, 신규 문장, 지연 검증, 예상 시간, 바로 시작 |
| 세트 | 상황·패턴·기능 필터, 미리 보기, 내 학습 추가 |
| 내 문장 | 학습 상태·다시 볼 문장·즐겨찾기·검색·개인 메모 |
| 기록 | 달력, 예정/실제 학습, 회상 검증, 다음 복습, 목표 진행 |

설정은 프로필에서 연다. 관리자 화면은 별도 /admin 경로와 레이아웃을 사용한다.

### 한 세션의 흐름

1. 정답 노출 전에 예정된 지연 검증을 우선 진행한다.
2. 복습할 문장의 상황/한국어 의미만 보여 준다.
3. 사용자가 말하거나 직접 입력한다. ‘기억 안 남’도 정상 선택이다.
4. 답을 제출하거나 회상 시도를 마친 뒤 정답·음원·차이를 보여 준다.
5. 실패하면 의미 단위로 짧게 다시 익힌다. 다른 문장 2~3개 이후 다시 묻는다.
6. 시간 예산이 남으면 신규 문장을 배정한다.
7. 오늘 확인된 성과와 다음 복습을 보여 준다. 미완료는 다음 방문으로 이어진다.

신규 문장은 먼저 상황·뜻·음원을 이해하고 짧게 따라 말한 후 가려서 시험한다. 따라 말하기 자체는 회상 통과가 아니다. 회상 연습 직전에 같은 정답 음원을 들려주지 않는다.

무한 반복을 피하기 위해 같은 세션에서 연속 실패하면 예: 3회 후 문장을 쪼개 설명하고 다음 세션으로 넘긴다. 실패 횟수 자체로 벌점을 부여하지 않는다.

## 5. 체크와 암기 검증

사용자 조작과 실제 학습 증거를 분리한다.

| 항목 | 의미 | 다음 학습에 미치는 영향 |
|---|---|---|
| 봤어요 | 내용·음원 확인 | 회상 성공에 포함하지 않음 |
| 외운 것 같아요 | 사용자 자기평가 | 확인 테스트 제안; 검증 상태 자동 승급 없음 |
| 직접 입력 성공 | 정답을 보지 않고 허용 답안 입력 | 입력 회상 증거로 기록 |
| 말하기 자기확인 | 말한 뒤 정답과 스스로 비교 | 별도 말하기 연습 이력; 객관 검증으로 표시하지 않음 |
| 다시 볼게요 | 어려운 문장 표시 | 우선 복습 및 메모 |
| 잠시 중지/제외 | 사용자의 학습 관리 | 이력 보존, 현재 범위와 최초 목표 범위 별도 표시 |

입력 검사는 대소문자·문장부호 등 의미 없는 차이를 정규화하되, 부정·시제·수량·주체처럼 의미를 바꾸는 차이는 유지한다. 축약형·대체 표현은 검수된 허용 답안으로 관리한다. 오탈자 제안은 제공하되 사용자가 수정한 답을 최초 무도움 정답으로 바꾸지 않는다.

정답이 의미상 타당하지만 등록되지 않았을 때 ‘다른 표현 신고’ 경로를 제공한다. 검수 전에는 실패/미확정 이력을 그대로 두고 사후 판정은 감사 이력으로 추가한다. 자유 표현을 문자 일치만으로 ‘틀린 영어’라고 단정하지 않는다.

초기 검증 라벨은 ‘입력 회상 확인’으로 한정한다. 키보드 자동완성·붙여넣기 등의 오염 가능성은 자기학습 서비스의 한계이며 가능한 범위에서 관찰·표시한다. 고부담 인증시험 수준의 부정 방지 기능은 만들지 않는다.

### 상태와 제안 통과 규칙

- 미학습 → 학습 중 → 지연 회상 확인 → 유지 확인. 실패하면 재학습 필요 표시.
- 학습 중: 같은 세션에서 한 번 성공해도 이 상태다.
- 지연 회상 확인: 무힌트 입력 성공을 서로 다른 학습일에 3회 기록하고, 각 성공은 직전 관련 노출로부터 24시간 이상, 마지막 성공은 7일 이상 떨어져 있어야 한다.
- 유지 확인: 지연 회상 확인 이후 직전 관련 노출로부터 30일 이상 지난 무힌트 입력 검증에 성공한다.
- 같은 문장의 열람·음원 청취·자기평가·다른 세트 연습도 관련 노출로 기록한다. ‘마지막 성공’만 보고 긴 지연을 판정하지 않는다.
- 실패 후 과거 성과는 지우지 않되 현재 상태는 재학습 필요로 바꾼다. 승급에 쓰는 연속 성공 묶음은 다시 쌓는다.
- 검증 기한이 지나면 ‘마지막 확인일/재확인 필요’를 표시한다. 영구 완성이나 기억 확률 100%는 표시하지 않는다.

이 기준은 초기 운영 가설이며 학습자 수준·문장 길이·실측 부담에 따라 버전 관리한다. 세트 진도는 ‘도입한 문장 수’, ‘지연 검증 문장 수’, ‘유지 확인 문장 수’를 따로 보여 준다. 일부 문장을 제외해서 최초 목표가 모두 달성된 것처럼 표시하지 않는다.

## 6. 날짜별·요일별·주기별 일정

**사용자가 정하는 학습 가능 시간과 문장별 복습 필요 시점을 분리한다.**

| 설정 | 예시 | 동작 |
|---|---|---|
| 날짜별 | 11월 1일 시작, 11월 20일 여행; 특정 날짜 추가 | 시작/목표일과 날짜별 예외·달력 기록 |
| 요일별 | 월·수·금 21시, 일요일 주간 점검 | 선택 요일의 학습 창에 문장 배정 |
| 주기별 | 기준일부터 2일마다 10분 | 기준일을 유지해 반복 창 생성 |
| 문장별 기억 복습 | 지난 테스트 실패/성공에 따라 다름 | 문장별 due_at 산출 후 학습 창에 배정 |

기본 반복 규칙은 ‘요일’ 또는 ‘N일마다’ 중 하나다. 날짜별 추가·휴식 예외가 우선한다. 주간 점검은 별도 이벤트이며 중복 문항은 한 번만 처리한다.

서버에는 UTC 시각과 사용자 IANA 시간대를 저장한다. N일 주기는 로컬 달력일 기준으로 계산하고 DST·여행 시 시간대 변경을 다룬다. 과거 이력의 학습일과 당시 시간대는 바꾸지 않는다. 미응시 일정은 완료 처리하거나 과거 날짜로 소급하지 않는다.

예: 월·수·금 학습자가 금요일 공부한 문장의 복습 필요 시점이 토요일이면 다음 월요일 창에 배정한다. 원래 due_at과 실제 배정일을 모두 남기고, 사용자에게 주말 3분 추가 복습 선택지를 제공한다. 학습 가능 요일을 무시한 강제 알림은 보내지 않는다.

‘여행 전 100문장’의 일정이 부족하면 새 문장 수·유지 검증 가능 범위를 보여 준다. 목표일 도달만으로 암기 완료 처리하지 않는다. N일 주기와 반복 테스트는 유저의 예약 방식과 문장별 기억 정책이라는 서로 다른 설정이다.

## 7. 복습 엔진

### MVP: 설명 가능한 규칙 기반 간격

첫 학습의 무도움 성공 후 다음 간격을 1일 → 3일 → 7일 → 14일 → 30일로 늘리는 초기 정책을 사용한다. **각 숫자는 직전 유효 회상 이후의 간격**이다. 매번 예정대로 성공한다면 누적 복습일 예시는 1·4·11·25·55일이다. 달력 학습 창에 맞추면 실제 날짜는 달라진다. 이 수열을 보편적으로 최적이라고 주장하지 않는다.

- 독립적인 무힌트 첫 시도 성공: 해당 복습 단계 다음 간격으로 진행.
- 무힌트 정답이나 사용자가 ‘어려웠음’ 표시: 같은 단계 간격 유지; 응답 시간만으로 오답 처리하지 않음.
- 힌트/정답 노출/오답: 무도움 성공에 포함하지 않고 재학습 후 1일 간격부터 재시작. 기존 이력은 보존.
- 같은 세션 재시도: 연습 결과로 남기고 여러 지연 성공으로 계산하지 않음.
- 자율 추가 연습: 예정 복습을 한 번 대체할 수 있는지는 실제 지연 조건으로 판단. 기준 미달이면 상태 승급 없음. 노출 시각은 항상 갱신.
- 주간 테스트: due 복습과 합쳐 한 이벤트로 처리. 정답 노출 전 첫 시도만 지연 검증에 사용.
- 말하기 자기확인 전용 모드는 별도 자기평가 일정이며 입력 검증 상태를 대신 승급시키지 않는다. 두 모드 모두 같은 문장의 노출 사실은 공유한다.

### 하루 학습량과 밀린 복습

고정 ‘복습 80%, 신규 20%’ 대신 사용자의 시간 예산을 우선한다. 실측 문항 소요 시간으로 복습 부담을 예측하고 초기에는 보수적인 기본값을 쓴다.

우선순위: 예정된 지연 검증 → 최근 실패 및 밀린 필수 문장 → 일반 예정 복습 → 신규 문장. 장기 지연 문장이 계속 밀리지 않도록 연체 일수에 따라 우선도를 높인다. 응용 연습은 처음에는 주간 점검에 소량 포함한다.

복습만으로 예산이 차면 신규 배정을 0개로 줄인다. 7일 부재 후 돌아오면 ‘오늘 3분 재시작’과 남은 학습량을 보여 주고 복구 일정을 분산한다. 학습 중지·세트 해제는 다른 활성 세트에 공통으로 있는 문장의 복습까지 중지하지 않는다.

### 2차: FSRS 비교 도입

FSRS는 복습 이력과 결과로 기억 상태를 추정해 간격을 정하는 후보이다. 기본 파라미터로 시작할 수 있으므로 개인 데이터가 없어서 원천적으로 사용할 수 없는 기술은 아니다. 다만 이 제품은 자기평가·입력·말하기를 분리해야 하므로 신호 설계와 이력 품질을 먼저 검증한다. 공식 알고리즘과 TypeScript 구현을 확인했다 [S5, S6].

도입 전 해야 할 일: 결과를 Again/Hard/Good/Easy 등에 매핑하는 규칙 검증, 힌트·자기평가·동일 세션 재시도 분리, 과거 이벤트 재현, 규칙 기반 정책과 부담/회상률 비교, 알고리즘 버전 고정·롤백. 입력·말하기 성과를 단일 점수로 섞지 않는다.

목표 유지율 0.9 등의 설정은 모델의 목표 확률이며 사용자의 실제 암기율을 보증하지 않는다. 개인 파라미터 최적화는 데이터 충분성과 검증 성능을 확인한 뒤 적용한다. 라이브러리 채택·버전·라이선스 확인은 구현 단계에서 재검토한다.

## 8. 테스트 유형과 피드백

| 테스트 | 단계 | 검증하는 것 | 출시 |
|---|---|---|---|
| 뜻/표현 선택 | 첫 이해 | 알아보기 | 필요한 콘텐츠에만 보조 |
| 빈칸·단어 순서 | 학습 중 | 구조 연습 | 2차; 완전 회상으로 계산 안 함 |
| 상황/한국어 → 전체 문장 입력 | 일상 복습 | 단서에서 문장 회상 | MVP 핵심 |
| 상황 → 소리 내어 말하기 → 정답 비교 | 일상 복습 | 자기확인 말하기 연습 | MVP 핵심 |
| 음성만 듣고 의미 파악 | 별도 듣기 능력 | 듣기 이해 | 2차 |
| 슬롯·상황 변형 | 주간 점검 | 패턴 응용 | MVP에 검수된 소량 문항 |
| 무작위 누적 테스트 | 주간 | 세트 순서 없이 회상 | MVP |
| 7일·30일 추적 테스트 | 효과 측정 | 학습 시작 후 시점별 유지 성과 | MVP |
| 상대방 대사에 답하기·역할극 | 응용 | 대화에서의 사용 | 2차; 인간 평가 파일럿은 선행 가능 |

평가형 테스트는 해당 세션의 정답 노출 전에 진행하고, 첫 시도 결과를 고정한 후 피드백·재학습한다. 테스트 종료 후 틀린 문장은 자동으로 복습에 돌아간다.

틀린 부분만 강조하고 ‘핵심 의미가 달라짐’, ‘목표 패턴 미사용’, ‘철자 수정 필요’ 등을 구분한다. AI가 필요하면 설명·대체 표현 초안 생성에 먼저 적용한다. 정답 승인과 핵심 학습 상태 변경을 불확실한 LLM 단독 판정에 맡기지 않는다.

응답 시간은 회상 노력의 참고값으로만 사용한다. 긴 문장, 키보드 속도, 접근성 요구 때문에 모두에게 5초 같은 제한을 통과 조건으로 강제하지 않는다. 음성 인식이 잘됐다는 사실도 발음이나 회화 유창성 인증과 다르다.

## 9. 관리자

별도 관리자 홈에서 콘텐츠 작업과 학습 운영을 관리한다.

- 세트 작성/복제/정렬/태그/검색/발행 예약/비공개/보관.
- 문장 원본과 세트 연결 관리; 이미 존재하는 문장 검색으로 중복 방지.
- 표준 문장·번역·상황 질문·허용 답안·힌트·음원 등록.
- 스프레드시트형 편집 및 CSV 가져오기: 미리 보기 → 필수값·중복 검사 → 오류 행 반환 → 확정 반영.
- 초안 → 검수 대기 → 발행 → 보관. 최소 파일럿에서는 동일 운영자가 단계별 체크리스트로 수행할 수 있고, 확대 시 작성·검수 권한을 분리한다.
- 모바일 학습 미리 보기로 정답 누출, 힌트 난도, 대체 표현, 음원 일치 점검.
- 문장별 오답률·반복 실패·정답 신고·중도 이탈·검증 표본 수 확인.
- 사용자별 상세 열람은 지원에 필요한 범위로 제한하고 관리자 접근·변경 감사 기록을 남김.

콘텐츠 수정 정책: 오탈자 수정은 버전과 변경 이력을 남기고 학습 이력을 유지한다. 의미·정답·학습 목표가 바뀌면 새 버전/학습 항목으로 분기하고 재확인 필요를 표시한다. 과거 답안을 새 정답으로 조용히 덮어쓰지 않는다. 발행 중 세트 변경은 사용자에게 추가 문장 수와 변경 내용을 표시한다.

관리자 인가와 사용자 데이터 소유권 검사를 서버에서 매 요청 수행한다. 화면을 숨기는 것만으로 권한을 대체하지 않는다.

## 10. 모바일 웹과 기술 설계

사용자가 확정한 구조: Next.js 최신 안정 버전의 TypeScript 반응형 웹·서버 API를 Vercel에 배포하고, Prisma로 Supabase PostgreSQL에 접근한다. 인증은 Supabase Auth, 음원은 Supabase Storage, 예약 실행은 Supabase Cron을 활용한다. 한 Next.js 프로젝트로 시작하고 복습 계산을 독립 모듈로 둔다. 정확한 버전 정책·연결·마이그레이션·배포 환경은 개발 실행 계획에 정의하며 요금제는 실제 운영 조건에 따라 결정한다.

| 구성 | 책임 |
|---|---|
| 사용자 웹 | 학습 화면, 답안 제출, 세트·일정 관리 |
| 관리자 웹 /admin | 콘텐츠 검수·발행, 운영 조회 |
| 서버 API | 인증/인가, 채점 규칙, 학습 이벤트 저장, 복습 계산 |
| DB | 문장/세트 버전, 사용자 계획, 원본 응시 이력, 현재 상태 |
| 음원 저장소 | 검수된 표준 음원 배포, 버전 연결 |
| 예약 작업 | 학습 창·알림 대상 계산, 중복 발송 억제 |
| PWA | 홈 화면 실행, 캐시·재시도, 지원 환경의 알림 |

알림은 iOS 16.4 이상에서 홈 화면 웹 앱 등 플랫폼 조건과 권한이 필요하다 [S7]. 일반 브라우저 방문만으로 모든 기기에 정시 푸시가 된다고 설계하지 않는다. 지원 감지, 설치 안내, 앱 내 오늘 할 일, 알림 거절 상태를 제공한다. 조용한 시간·발송 상한·묶음 알림을 두고 OS 전달 지연을 허용한다.

표준 음원은 원어민 녹음 또는 검수된 TTS 파일을 사전 제작한다. TTS 결과가 정확하다고 자동 가정하지 않는다. 실시간 TTS 호출보다 같은 음원을 재사용해 비용·일관성을 관리한다.

브라우저 SpeechRecognition은 지원 범위가 제한되고 일부 구현은 서버로 음성을 전송한다 [S8]. MVP는 마이크 없이도 완결되며 말하기 후 자기확인·입력을 제공한다. 자동 음성 평가를 도입할 때는 처리 동의·보관 기간·삭제·인식 실패 처리와 재시도 비용을 함께 설계한다. 인식 실패는 기억 실패로 기록하지 않는다.

초기에는 온라인 학습을 기준으로 한다. 제출 중 연결이 끊기면 답안을 임시 보존하고 ‘동기화 대기’로 표시한다. 클라이언트 이벤트 ID로 재전송 중복을 방지하고 서버 확인 후 기록 완료 표시를 한다. 완전 오프라인 세트 다운로드와 여러 기기 충돌 병합은 2차 범위다.

접근성: 음원 대본·문자 입력 대안, 키보드 탐색, 스크린리더 라벨, 충분한 터치 영역, 글자 크기 확대, 색 이외의 정오답 표시. 360px 폭에서 핵심 학습이 가능하도록 검증한다.

네이티브 앱은 유지 성과와 재방문이 검증된 뒤 검토한다. 향후 앱에서도 같은 콘텐츠·응시·복습 API를 재사용할 수 있게 UI와 도메인 규칙을 분리한다.

## 11. 데이터와 지표

주요 개체: User, Sentence, SentenceVersion, PromptVariant, Set, SetSentence, Enrollment, StudyPlan, Session, ReviewEvent, ExposureEvent, UserSentenceState, ContentIssue, NotificationSubscription, AuditLog.

ReviewEvent는 응시 시각, 당시 시간대·학습일, 콘텐츠/채점/정책 버전, 능력 유형, 문항 형태, 최초 답안 결과, 힌트/정답 공개 여부, 응답 시간, 자기평가 여부, 세션·멱등 키를 저장한다. 현재 상태는 이벤트로 재현할 수 있어야 한다. 원문 입력은 분석 필요·개인정보 최소화 원칙에 맞춰 보관하고 음성 원본은 MVP에서 서버 수집하지 않는다.

달력·통계는 원본 이력으로 계산한다. 현재의 ‘외운 문장 수’ 스냅샷으로 과거 날짜별 학습 횟수를 재구성하지 않는다. 여러 세트의 동일 문장은 전체 성과에서 문장 ID 기준으로 중복 제거한다.

### 성공 지표

| 지표 | 정의 | 오해 방지 |
|---|---|---|
| 7일/30일 무도움 회상률 | 최초 학습 코호트의 해당 시점 평가에서 첫 무힌트 정답 수 / 실제 응시 문항 수 | 응시율·누락·표본 수·중간 학습 횟수·최근 노출 간격 함께 표시 |
| 검증 문장 수 | 능력 유형별 지연 조건을 충족한 고유 문장 수 | 입력과 말하기 자기평가 분리 |
| 복습 이행률 | 기간 중 예정된 고유 복습 항목 중 완료 항목 비율 | 재시도로 분자 부풀리지 않음 |
| 유지 학습 효율 | 지연 검증 성공 문장 수 / 실측 활성 학습 시간 | 탭 방치 시간 제외 기준 명시 |
| 복구율 | 일정 기간 부재한 사용자 중 복귀 후 복습 재개 비율 | 단순 앱 방문과 구분 |
| 응용 성공률 | 새로운 상황 단서·패턴 문제의 첫 시도 성공 비율 | 기존 문장 암기와 따로 표시 |

7일·30일 추적 평가는 최초 학습 후 7±2일, 30±3일이라는 초기 관찰 창을 사용한다. 기간 밖 응시는 별도 집계한다. 이는 복습을 허용한 학습 프로그램의 성과이며 ‘30일간 아무 노출 없이 기억했다’는 의미가 아니다. 앞의 유지 확인 배지는 최근 관련 노출로부터 30일 간격을 요구하므로 서로 다른 지표다.

평가 문항은 완료자·잘 외운 문장에만 편향되지 않게 처음 선택한 대상에서 사전 표집한다. 미응시는 임의로 정답/오답으로 만들지 않고 별도 누락률을 표시하며, 전체 배정 대비 검증 성공 비율도 병기한다. 앱 내 일상 평가에서 남는 자기평가 편향을 인간 평가 파일럿으로 확인한다.

## 12. 범위와 개발 순서

### MVP 필수

- 검수된 세트와 표준 음원, 관리자 CRUD·가져오기·발행.
- 회원·세트 선택·문장 관리, 날짜·요일·N일 반복 일정.
- 가리고 입력/말하기 자기확인, 단계별 힌트, 정답 비교, 실패 재학습.
- 규칙 기반 문장별 복습, 주간 누적 테스트, 추적 평가.
- 오늘 화면·달력·상태별 진도·부담 조절·복귀 흐름.
- PWA 설치 안내와 지원 환경의 알림, 제출 재시도, 역할/소유권 보호.

### 2차

FSRS 비교·도입, 음성 인식과 검수 가능한 평가, 녹음 재생, 듣기 전용 학습, 개인 문장 추가, 다양한 패턴 훈련, 완전 오프라인, 다국어 콘텐츠 확대.

### 효과 검증 후

AI 역할극, 네이티브 앱, 교육기관·그룹 기능, 과금. 핵심 검증 기준을 느슨하게 만드는 포인트·랭킹·연속 출석 경쟁은 우선하지 않는다.

## 13. 인수 기준과 검증 방법

1. 관리자가 세트 작성→검수→발행하면 일반 사용자가 검색·선택·학습 가능하다. 초안·보관 콘텐츠 노출 정책을 E2E로 검증한다.
2. 외웠다는 체크만으로 지연 검증/유지 확인이 올라가지 않는다. 자기평가·입력·말하기 이력을 분리한 단위 테스트로 검증한다.
3. 힌트 사용, 정답 공개 후 입력, 같은 세션 재시도는 최초 무도움 정답에 포함되지 않는다.
4. 동일 문장이 두 활성 세트에 있어도 전체 복습 항목·검증 문장 수가 중복되지 않는다. 한 세트 해제 시 다른 세트 학습은 유지된다.
5. 1·3·7·14·30일의 상대 간격, 실패 후 재학습, 일정 창 이동, 최근 노출 조건을 고정 시계 테스트로 검증한다.
6. 월수금·2일 간격·특정 날짜 휴식/추가·시간대 변경·DST·7일 부재의 일정을 테스트한다. 원래 due_at과 배정일을 구분한다.
7. 주간 테스트와 복습이 겹쳐도 상태가 두 번 갱신되지 않는다. 재전송도 이벤트 하나로 처리한다.
8. 의미를 바꾸는 답안 오류와 등록된 허용 표현의 경계를 고정 콘텐츠 사례로 검증한다. 예: 부정·수량은 실패, 문장부호 차이는 허용.
9. 콘텐츠 의미 변경 후 과거 이력과 당시 채점 버전을 조회할 수 있다. 새 버전이 과거 검증을 무조건 승계하지 않는다.
10. 사용자 간 데이터 접근과 비관리자의 관리자 API 접근을 서버에서 거부한다. 관리자 역할 회수는 후속 요청에 반영된다.
11. 알림 미지원·권한 거절·마이크 미지원·네트워크 단절에서도 핵심 학습과 재시도 경로가 동작한다.
12. 최신 실기기 iOS Safari/PWA, Android Chrome에서 핵심 흐름과 360px 화면을 확인한다. PWA 알림·음원 재생은 자동 테스트만으로 완료 주장하지 않는다.
13. 통계는 분자·분모·고유 문장·미응시·평가 창을 명시한다. 원본 이벤트 표본과 계산값을 대조한다.

구현 검증에는 도메인 단위 테스트, DB/인가 통합 테스트, 핵심 E2E, 린트·타입 검사·빌드를 포함한다. 현재는 기획 문서만 작성했으므로 앱 동작·학습 효과를 검증했다고 보고하지 않는다.

## 14. 파일럿과 주요 위험

파일럿 제안: 20~30명, 약 6주, 공통 핵심 문장과 개인 선택 세트를 조합한다. 이는 사용성·운영·초기 효과 신호 탐색 규모이며 통계적 우월성 입증 규모로 간주하지 않는다. 최초 30일 추적 창을 충족하는 코호트만 해당 지표에 포함한다. 30일 무노출 유지 배지까지 평가하려면 더 긴 관찰이 필요하다.

초기 제품 목표 가설: 7일 추적 무힌트 입력 회상률 80%, 30일 70%, 추적 평가 응시율 70% 이상, 정규 세션 활성 시간 중앙값 10분 이내. 이 수치는 연구에서 보장한 성능이 아니며 baseline을 측정한 뒤 조정한다. 회화 전이는 별도 상황 질문을 인간 평가자가 기준표로 채점하고 평가자 간 불일치를 확인한다.

알고리즘 또는 학습법 비교 시 학습량·콘텐츠 난도·사전 능력을 통제한다. ‘더 오래 공부해서 더 잘 외움’과 ‘같은 시간에 더 잘 외움’을 구분하고, 인과적 우월성을 주장하려면 별도 표본 설계·무작위 비교가 필요하다.

| 위험 | 대응 |
|---|---|
| 클릭으로 암기 상태를 부풀림 | 자기평가와 지연 검증 분리, 첫 응시 보존 |
| 번역만 외워 대화에 사용하지 못함 | 상황 단서 다양화·패턴 응용·별도 말하기 파일럿 |
| 복습 부채로 포기 | 신규 자동 감량, 시간 예산, 짧은 복귀 세션 |
| 틀린/부자연스러운 문장 암기 | 콘텐츠 검수·음원 대조·신고·버전 관리 |
| 타당한 대체 답안을 오답 처리 | 허용 답안 관리, 판정 미확정/신고 경로 |
| 음성 인식 오류를 기억 실패로 오해 | 입력·자기확인 대안, 기술 실패 분리 |
| 알림 미도달로 학습 누락 | 앱 내 일정 원본, 설치/권한 상태 안내, 알림에만 의존하지 않음 |
| 성과 지표의 생존자 편향 | 최초 대상 코호트·평가 응시율·누락·최근 노출 병기 |
| 기능 과다로 핵심 학습 검증 지연 | 작은 콘텐츠 묶음과 단일 회상 루프부터 출시 |

완료 조건: 관리자 발행→사용자 선택→회상→실패 재배정→날짜별 검증 기록이라는 흐름이 인수 기준을 충족하고, 파일럿에서 무엇을 얼마나 기억했는지 평가할 수 있어야 한다. 단순 화면 완성이나 출석 횟수로 제품 목적 달성을 선언하지 않는다.
